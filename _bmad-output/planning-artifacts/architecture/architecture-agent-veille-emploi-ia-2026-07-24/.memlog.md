- (version) Versions verifiees sur le web le 2026-07-24 : anthropic Python SDK 0.119.0, feedparser 6.0.12, Python 3.11 installe, uv installe. Modele pour accroches : Claude Haiku 4.5 (claude-haiku-4-5-20251001), le moins cher.
- (question) POINT CRITIQUE : le brief supposait une publication en 'Artefact claude.ai a URL fixe'. Or un Artefact ne peut PAS etre regenere par un script nocturne autonome (planificateur Windows) - il exige une session claude.ai. Il faut un mecanisme de publication scriptable. Candidat privilegie : GitHub Pages (le script commit le HTML dans le repo, GitHub sert a URL fixe, gratuit, accessible mobile). Bonus : le repo existe deja pour l'archive Markdown versionnee. A trancher avec l'utilisateur.
- (decision) Publication = GitHub Pages : le script commit le HTML dans un depot servi a URL fixe, gratuit, accessible mobile. Le meme depot heberge l'archive Markdown versionnee. Remplace l'hypothese 'Artefact claude.ai' du brief, incompatible avec une execution nocturne autonome. Previent : mecanismes de publication divergents.
- (decision) Etat persistant = SQLite (stdlib Python, rien a installer) : source unique de verite pour le 'deja vu par source' (dedoublonnage) et l'etat de sante des sources. Previent : deux proprietaires de l'etat de dedoublonnage, fragilite des fichiers JSON quand le volume grossit.
- (decision) Paradigme = pipes-and-filters (pipeline) : collecte -> dedoublonnage -> filtrage/scoring -> enrichissement (accroches) -> rendu -> publication. Chaque etage est une etape discrete avec un contrat de donnees clair. Previent : des etages qui se melangent et lisent dans les internes des autres.
- (decision) Connecteurs de sources derriere une interface uniforme (pattern adapter) : chaque type (RSS, API JSON, scraping) implemente un contrat commun et produit des Items dans un format interne unique. Previent : le code de collecte couple aux specificites de chaque source ; permet d'ajouter une source sans toucher au pipeline.
- (decision) Sources et Profil sont de la CONFIGURATION, pas du code : un fichier sources (YAML) et le fichier profil pilotent le comportement. Previent : modifier le code pour ajouter/retirer une source ou re-regler le filtrage. Realise l'exigence PRD FR-1/FR-5.
- (decision) Item = la forme interne canonique unique que tous les connecteurs produisent et que tous les etages aval consomment (champs invariants : id_source, guid/url, titre, date, langue, registre, contenu brut). Previent : deux connecteurs emettant des formes incompatibles.
- (decision) Isolation des pannes : une source qui echoue est capturee, journalisee dans l'etat de sante, et n'interrompt jamais le run. Previent : une seule mauvaise source qui tue le digest. Realise PRD FR-2.
- (decision) Frontiere LLM : la generation d'accroches est le SEUL point qui appelle l'API Claude, derriere un module unique. Previent : des appels API disperses, un cout non maitrise, un modele difficile a changer.
- (decision) Job nocturne idempotent : relancer la meme nuit produit le meme digest (upsert par date), ce qui permet la reprise sur echec. Previent : doublons d'archive et double publication. Realise PRD FR-11.
- (decision) Secrets (cle API Claude, tokens Kaggle/Semantic Scholar) dans un fichier .env local NON versionne ; jamais dans le depot publie. La sortie publiee (HTML + archive MD) ne contient aucun secret.
- (decision) Revue adversariale : conflit AD-5 vs AD-9. Correction (AD-11) : l'etat 'deja vu' n'est valide qu'APRES publication reussie, dans la meme transaction. Un pipeline qui plante avant la publication ne marque rien ; la reprise reconsidere les memes items. Previent la perte silencieuse d'items lors d'un echec en milieu de pipeline.

- (decision) Correction post-revue-de-code (Story 1.1) : la convention 'Identite d'item' contredisait sa propre implementation. Tranche : guid = identifiant natif du flux (entry.id/<guid>) en priorite, puis URL, puis hash SHA-256 en dernier repli. Raison : un identifiant natif est concu pour etre permanent, une URL peut deriver (tracking, migration) sans que le contenu change, ce qui casserait le dedoublonnage cross-nuit (Story 3.4, AD-11). Le champ url reste distinct, dedie au lien cliquable. Aucun changement de code requis - le code implementait deja cette regle, seule la documentation (spine + story 1.1 Task 4) etait en contradiction avec lui.
